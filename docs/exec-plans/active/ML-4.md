## Цель

Получить проверяемое улучшение ROC-AUC на групповых внутренних validation folds только внутри зафиксированного development, сохраняя контроль утечек, памяти и стоимости обучения.

## Объём и шаги

1. Закрыть принятый план ML Foundation; зафиксировать протокол ML-4 и ресурсы. Не читать внешний holdout для выбора конфигураций.
2. Построить один сохраняемый 3-fold split по группам идентичных векторов, стратифицированный по наличию положительной метки в группе; внутри training части каждого fold создать отдельный групповой stop split. Проверить отсутствие пересечений и классы.
3. Провести диагностику development: дубли и конфликтующие метки, нулевая доля и константы, различия классов, разбор feature importance и распределения score. Привязать выводы к наблюдениям, сформулировать гипотезы.
4. Запустить небольшой набор на одинаковых folds: исходные параметры CatBoost, одну осмысленную вариацию CatBoost, одну конфигурацию LightGBM при доступной зависимости. Для каждого fold выбирать число деревьев только по отдельному stop split, затем обучать на всём training fold и измерять train/validation ROC-AUC, AP, gap, время, RSS. Хранить уникальный run ID, параметры, seed, fold IDs, код и версию данных в JSON и модели в локальном `artifacts/runs/`.
5. Зафиксировать диагностические Precision@K/Recall@K при K=100, 500, 1000 строк на каждом validation fold; при равных score разрешать ничью по локальной позиции строки. K выбраны до обучения как исследовательские размеры очереди, не как согласованная бизнес-ёмкость. Сохранять агрегированные квантили score по классу, без строк данных.
6. После первой серии выбрать проверяемые гипотезы для продолжения: depth/регуляризация, imbalance, числовые параметры и отбор признаков. Отбор выполнять только на training части fold. Закрывать этап лишь после достаточной проверки устойчивости, review package, независимого ревью и принятия владельцем.

## Критерии завершения этапа

- Все сравниваемые модели используют одинаковые групповые validation folds; stop split не пересекается с validation fold.
- Метрики и ресурсы реальных запусков сохранены без выдуманных значений, каждый запуск имеет отдельный каталог и ссылку из журнала.
- Есть оценка вариации по folds, анализ переобучения, диагностик и выигравших/неудачных гипотез; просмотренный внешний holdout не применяется в подборе.
- Проверки кода и инвариантов прошли; review package подготовлен и опубликован только после отдельного разрешения; независимый reviewer и владелец приняли результат.
