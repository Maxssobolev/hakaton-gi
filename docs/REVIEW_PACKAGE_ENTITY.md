   строк — cross-fitting (`entity_delivery.py`, `research/entity_lookup/rowcv*.py`); `tests/test_entity.py`
   проверяет независимость признаков строки от её метки. Нет ли пути, где строка видит свою метку
   (например, точные дубликаты в TE: подмножества `row_hash % 5`)?
2. **Валидность построчной CV.** Аргумент «TEST — случайные строки» (7.65% против 7.67%) и вывод, что групповая CV
   систематически занижает пользу LK/BP на TEST. Holdout отделён по группам — проверка там консервативна?
3. **Selection bias.** Конфигурация выбрана на seed 20261024; seed 20261026 — подтверждение по предрегистрированным

   (тест), против исследовательского эталона (2.2e-16), чистый murmurhash3 против sklearn (464315 слов).
5. **Допустимость по правилам соревнования** — kNN по меткам TRAIN без скрытых меток TEST и внешних данных.
6. **Приватность.** `entity_tables.npz`/`te_tables.npz` содержат агрегаты меток TRAIN по значениям/строкам — не
   публиковать; в Git не входят (`artifacts/` игнорируется).
