## Находка

TRAIN/TEST разделены **случайно по строкам**: точный дубликат вектора признаков в TRAIN есть у 7.65% строк TEST
при 7.67%, ожидаемых для случайного построчного split; доля TEST во всех децилях `index` — 0.30; сам `index`
не информативен (AUC 0.496). Многие строки — повторные снимки одной сущности: у пар с общим значением `feature_18`
медиана — 100% совпадающих столбцов, метки совпадают в 97–99.7% пар. Групповая CV (ML-4) по построению держит
такие повторы в одном fold, поэтому этот сигнал был невидим. Для лидерборда используется построчная CV.

## Модель (финальная сборка `entity-te15lkbp-nb-20261021T212050Z-7b1d4c1f`, релиз R1.2)

1367 raw → + TE15 (m=100; `row_hash % 5` cross-fitting) → + 16 признаков точных совпадений (`feature_10/17/18/19`,
блок 1065–1107, `feature_11`, 20–48, полный вектор; метки только строк TRAIN; значения, встречающиеся >200 раз,
игнорируются; текстовый ключ отключён) → + 5 признаков ближайшего партнёра по 43 полосам столбцов (совпадение
полосы; шаблоны, встречающиеся >20 раз, игнорируются) → LightGBM `lightgbm_rows65`, 214 деревьев, seed 42/43/44,
среднее логитов → при наличии текста `0.8·z(logit) + 0.2·z(NB)` с замороженными label-free константами TEST.
Признаки обучающих строк — cross-fitting по 5 случайным построчным подмножествам (`RandomState(20261025)`):
в таблицах значений строка не видит своей метки (общий prior TE включает её с весом ~1/248000). Без текста score в точности табличный. Код: `ml/features_v2.py`
(общий для обучения и инференса), `ml/entity_delivery.py`, `ml/inference.py` (`EntityPredictor`).
