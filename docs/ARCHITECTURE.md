# Архитектура

## Реализуемый сейчас поток

`TRAIN.csv` → проверка схемы → групповой development/holdout split по хэшу вектора признаков → предобработка внутри development → SGD Logistic Regression / CatBoost → метрики и локальные артефакты.

Код ML находится в `ml/`; команды и зависимости — в корневом README. Исходные данные не меняются. `artifacts/` содержит локальные отчёты, модели и схемы и не попадает в Git. Журнал подтверждённых запусков — [ML_EXPERIMENTS.md](ML_EXPERIMENTS.md). Ветка текста и финальный inference contract пока не реализованы.

`ml/cache.py` создаёт временные массивы из TRAIN.csv, проверяет их и публикует манифест последним. Кеш привязан к SHA-256 TRAIN, хэшу упорядоченной схемы и версии преобразования; при повторном обучении проверяются формат и SHA-256 файлов массивов. Повреждённый или старый кеш пересобирается с явным сообщением. `ml.verify` отдельно потоково сравнивает **каждую** строку признаков, меток и групповых хэшей с TRAIN.csv; эта полная проверка выполняется для контрольного этапа, а не при каждом предсказании модели.

## Целевая ML-подсистема и передача

После выбора модели появится переносимый Python-пакет с единым путём `input → проверка схемы → preprocessing → model → PredictionResult`. Он зафиксирует имена, порядок и типы 1 367 признаков, правила ошибок, обработку текста при его включении, версию модели и семантику score. Пакет должен загружаться без обучения и работать в закрытом контуре при наличии совместимых зависимостей. Если выберем ансамбль, в пакет войдут все его компоненты. Контракт с принимающими командами описан в [ML_INTERFACE](ML_INTERFACE.md); пока это проект интерфейса, а не готовый API.

Backend и frontend относятся к отдельным командам. Для поиска по `index` им понадобится согласованный источник подготовленных признаков; `index` не является предиктором текущего baseline. Для нового объекта нужен полный поддерживаемый вектор признаков. Наша команда не реализует HTTP-сервис, приложение, его базу данных или инфраструктуру развёртывания.

Архитектурный риск: имена признаков обезличены, поэтому пользовательская форма с понятными полями невозможна без дополнительного словаря от организаторов. Также пока неизвестно, доступны ли все признаки до события банкротства.
