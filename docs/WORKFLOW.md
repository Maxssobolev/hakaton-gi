# Рабочий процесс и принятие изменений

Репозиторий — источник истины для решений, планов и результатов. Перед изменением прочитайте AGENTS.md, относящиеся документы и активный план; проверьте git status и diff. Делайте минимальное связное изменение. После него запускайте реальные проверки, изучайте весь diff, обновляйте статус и сообщайте точные результаты. Метрики, проверки и решения нельзя выдумывать.

## Роли и ворота между этапами

Codex — ML author: реализация, эксперименты, проверки и review package. ChatGPT в **отдельной сессии** — independent ML reviewer: читает опубликованный через GitHub код, Git diff, методологию и доказательства. Владелец проекта принимает результат и разрешает переход к следующему крупному этапу. Самопроверка автора не заменяет независимое ревью.

После существенного этапа автор завершает scope, выполняет предусмотренные проверки, готовит review package по [шаблону требований](REVIEW.md) и сообщает владельцу о готовности. Для доступа reviewer нужен фиксированный Git-снимок: предпочтительно отдельная ветка и PR с ограниченным scope. Commit, push и публикация требуют отдельного разрешения владельца. После публикации reviewer выдаёт вердикт и замечания; автор устраняет blocker/important, повторяет проверки и при необходимости review. Только после принятия владельцем можно закрыть план и начать следующий крупный этап. Реальные результаты ревью и решение записываются в активном плане.

## Уровень риска

Локальные обратимые исправления требуют целевой проверки и самопроверки. Изменения протокола валидации, схемы данных, inference contract, зависимостей или архитектуры требуют execution plan и отдельной проверки результата. Для существенного ML-этапа нужен независимый reviewer и явное принятие владельцем перед закрытием плана. Недоступность независимого review фиксируется; автор не объявляет такой review проведённым. Число файлов не определяет риск.

Планы в docs/exec-plans/active/ описывают цель, критерии и реальные проверки. После принятия владельцем план можно перенести в completed/. STATUS.md — только текущий снимок; история остаётся в закрытых планах и ML_EXPERIMENTS.md. Существенные принятые решения фиксируйте отдельно; открытые гипотезы не называйте ADR.

Нельзя выполнять commit, push, merge, публиковать данные, отправлять submission или изменять внешнее приложение без отдельного разрешения владельца. Репозиторий GitHub публичный: перед публикацией проверить полный список файлов и staged diff; исходные CSV/TSV, записи людей, секреты и чувствительные артефакты не публиковать. Права на распространение исходного задания и иных материалов подтвердить до их включения в публичный checkpoint. Не применять force push к проверяемому commit без согласования. Исходные CSV/TSV не менять и не удалять.
