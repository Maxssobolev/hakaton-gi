Задание на хакатон
1. Задача
Разработать интеллектуальную систему для оценки вероятности банкротства физического лица на основе методов машинного обучения (ML).
Система должна включать:
	ML-модель, предсказывающую вероятность банкротства на основе табличных и текстовых данных;
	backend для обработки запросов и применения обученной модели;
	frontend для ввода данных и визуализации результатов предсказания.
2. Исходные данные
Каждый объект выборки соответствует физическому лицу и характеризуется 1367 признаками, включающими пользовательские характеристики и агрегированные показатели активности.
Предоставляемые файлы:
1. TRAIN.csv — 247 972 объекта. Обучающая выборка, содержащая:
	index — идентификатор объекта;
	target — целевая переменная: 1 — событие банкротства, 0 — отсутствие события;
	1367 признаков.

Основные группы признаков:
	пользовательские интересы;
	используемые устройства;
	социальное окружение;
	социально-демографические характеристики;
	интернет-активность.
2. TEST.csv — 106 274 объекта.
Тестовая выборка с аналогичным набором признаков, но без колонки target. Используется для получения предсказаний и оценки качества моделей в лидерборде.
3. Дополнительные текстовые данные.
Для части или всех объектов предоставляются дополнительные текстовые признаки, связанные с физическими лицами по идентификатору index.
Данные представлены в формате частотного словаря: «слово — количество упоминаний».
Участники могут самостоятельно выбирать способы обработки и использования текстовой информации, включая TF-IDF, текстовые эмбеддинги и другие подходы.


3. Требования к решению
3.1. ML-модель
Необходимо:
1.	Провести исследовательский анализ табличных и текстовых данных.
2.	Подготовить признаки для обучения модели.
3.	Обучить ML-модель для предсказания вероятности банкротства физического лица.
4.	Оценить качество модели на собственной валидационной выборке.
5.	Получить предсказания для TEST.csv и отправить их в лидерборд соревнования на платформе All Cups.
Основная метрика качества: ROC-AUC.
Разрешается использовать любые подходы к моделированию, соответствующие ограничениям программного обеспечения, установленным организаторами.
3.2. Backend
Необходимо разработать серверную часть приложения, которая обеспечивает загрузку обученной ML-модели и получение предсказаний.
Обязательные сценарии:
1.	Предсказание по идентификатору. Пользователь вводит index объекта из предоставленных выборок. Система извлекает соответствующие признаки и возвращает предсказание модели.
2.	Предсказание по набору признаков. Пользователь передаёт признаки нового объекта в поддерживаемом формате. Система выполняет предобработку данных и возвращает предсказание.
Повторное обучение модели при поступлении запроса не требуется.
3.3. Frontend и визуализация
Необходимо разработать интерфейс сайта или приложения, который позволяет:
1.	Ввести идентификатор объекта или передать данные нового объекта.
2.	Получить результат предсказания — вероятность банкротства.
3.	Отобразить результат в понятном для пользователя виде.
Формат визуализации команды выбирают самостоятельно.

3.4. Архитектура и автоматизация
Решение должно включать воспроизводимый процесс предобработки данных и применения модели.
Приветствуются:
	модульная архитектура;
	API для взаимодействия frontend и backend;
	автоматизация сборки, тестирования и развёртывания приложения (CI/CD);
	контейнеризация;
	обработка ошибок и валидация входных данных.

3.5. Презентация
Команда должна подготовить презентацию и провести защиту проекта.
На защите необходимо продемонстрировать:
	используемый ML-подход и достигнутое качество;
	архитектуру разработанного решения;
	продемонстрировать frontend приложения (скриншоты) или работу приложения (live demo);
	основные результаты и ограничения решения.
Требования к формату презентации

4. Порядок выполнения задания
1.	Анализ исходных данных.
2.	Подготовка признаков и обучение ML-модели.
3.	Валидация и оценка качества.
4.	Получение предсказаний на TEST.csv и отправка результатов в All Cups для корректировки  (не более 10).
5.	Разработка backend и frontend.
6.	Создание проекта и инфраструктуры в ОСБР ПО.
7.	Размещение приложения в проекте ОСБР ПО.
8.	Сборка приложения в ландшафте ОСБР ПО.
9.	Тестирование работоспособности приложения.
10.	Проверка кода модулем ПУТ ПО.
11.	Отправка результатов в All Cups для получения финальной оценки.
12.	Подготовка презентации и защита проекта.
Этапы могут выполняться параллельно.

5. Ожидаемые результаты
По итогам хакатона каждая команда должна представить:
1.	Файл с предсказаниями (.csv) для тестовой выборки, загруженный в лидерборд.
2.	Обученную ML-модель и код предобработки данных.
3.	Работоспособный прототип приложения с backend и frontend.
4.	Исходный код проекта в ОСБР ПО.
5.	Презентацию для защиты проекта.
6.	Сводные результаты проверки ПУТ ПО (слайдом презентации).
